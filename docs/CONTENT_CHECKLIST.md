# 知识页内容检查清单（标准 v2）

一页知识页要能独立带人学会一个节点：先建立直觉，再给出精确定义，完整走一遍推导，看一个算到底的例子，避开常见误区，用练习自查，并且每条事实都能追回一手来源。

`schemaVersion: 2` 的页面必须通过下面全部自动检查，CI 才会放行。手动检查由审核者在合并前完成。样板是 `content/pages/linear-algebra.json`。

```bash
npm run checklist -- linear-algebra          # 检查一页
npm run checklist -- --path ml-foundations   # 检查整条路径
npm run check                                # CI 同款：schema、图谱、清单、测试
```

## 页面结构（`lesson` 字段）

| 部分 | 字段 | 要求 |
| --- | --- | --- |
| 直觉 | `lesson.intuition` | 不靠公式讲清“为什么是这样”，可以用图像、物理或日常类比，至少 100 字 |
| 正式定义 | `lesson.definitions[]` | 至少 2 条；`term`（中文术语）、`english`、`statement`（精确陈述，条件写全）、`cite` |
| 完整推导 | `lesson.derivation` | `claim`（要证明或推出的结论）、`assumptions`、`steps`（至少 4 步，每步只做一件事）、`conclusion`、`cite` |
| 例子 | `lesson.example` | `problem`、`steps`（至少 3 步）、`answer`、`check`（如何独立验证答案）、`cite` |
| 常见误区 | `lesson.misconceptions[]` | 至少 3 条；`wrong`（学习者真实会说的错误说法）、`right`（纠正，最好附反例） |

`cite` 写作 `{ "source": "LA2", "at": "第 3.B 节 定理 3.21" }`。`source` 指向 `sources[].id`，`at` 必须精确到章节、定理或讲次，让审核者能翻到原文。

## 自动检查（CI 强制）

| 编号 | 检查项 | 通过条件 |
| --- | --- | --- |
| C01 | 摘要 | 不是模板句，30–220 字 |
| C02 | 直觉 | 至少 100 字 |
| C03 | 正式定义 | 至少 2 条，每条有术语、不少于 10 字的陈述和有效出处 |
| C04 | 完整推导 | 命题、至少 4 步、结论、有效出处 |
| C05 | 例子 | 题目、至少 3 步、答案、自检方式、有效出处 |
| C06 | 常见误区 | 至少 3 条，错误说法和纠正都完整；如有出处，出处必须有效 |
| C07 | 练习 | 至少 8 题；`XX-E01｜题目：…\n解析：…\n掌握检查：…` 三段格式；同一前缀，编号不重复 |
| C08 | 一手来源 | 至少 3 个已核验来源，各有 `id`、https 链接和 `checkedAt`；所有 `cite` 都指向已核验来源 |
| C09 | 完成标准 | 三级门槛都引用题号，不出现“了解、熟悉、掌握”这类无法检验的措辞 |
| C10 | 图谱一致 | 页面标题与图谱节点一致；`data/catalog.json` 里该节点的 `summary` 已替换为真实摘要 |
| C11 | 审核记录 | `docs/content-research/pages/<slug>.md` 存在，逐个列出已核验来源的链接，并有 `## 复核` 一节 |

“有效出处”指 `cite.source` 是本页一个已核验来源的 `id`，并且 `cite.at` 不为空。

## 手动检查（合并前由审核者完成）

| 编号 | 检查项 | 做法 |
| --- | --- | --- |
| M1 | 事实核对 | 打开每个 `cite` 指向的原文位置，确认定义、定理和结论与原文一致；不一致的改正或删除 |
| M2 | 推导可复算 | 按步骤独立重推一遍，每一步都能由前一步加上所写的假设得到 |
| M3 | 数值复核 | 例子和练习中的所有数值答案都用代码或精确计算复核，复核方式写进审核记录的 `## 复核` |
| M4 | 阶段与边界 | 不超出节点阶段，不使用图谱必要前置以外的知识；边界外的内容只点名、不展开 |
| M5 | 可学性 | 一位只掌握必要前置的读者能顺着“直觉 → 定义 → 推导 → 例子 → 练习”学下来，不需要跳到别处补课 |
| M6 | 发布 | 只有维护者抽查通过后，才把 `status` 从 `draft` 改为 `reviewed`；路径的 `status` 改为 `published` 后，CI 会要求路径上每个节点都达标且已审阅 |

## 审核记录模板

`docs/content-research/pages/<slug>.md`：

```markdown
# <标题> 审核记录

## 来源
- [LA1] <标题> — <URL> — 打开日期 YYYY-MM-DD — 核对了哪些章节

## 出处核对
- 定义「…」→ [LA2] 第 x 节：一致 / 已改正

## 复核
- 例子：<计算方式与结果>
- LA-E01…E12：<复核方式与结果>

## 待解决
- …
```
