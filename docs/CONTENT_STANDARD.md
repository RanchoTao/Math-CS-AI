# 知识节点内容标准 v1

本文件定义 Math-CS-AI 知识页面的长期内容规则。批量生成页面、人工编辑和后续 Agent 流水线都必须遵守这里的约束。

## 1. 页面对象

网站的基本对象是“知识节点”，不是“学校课程”。页面统一使用 `knowledge.html` 渲染。

节点类型固定为：

- `course`：可形成完整课程的知识模块；
- `practice`：实践、方法与规范；
- `tool`：工具与工程环境；
- `frontier`：研究方向与高级专题。

“跨学科前置”属于关系属性，不是节点类型。

## 2. 图谱是关系事实源

领域、层级、学科群、必要前置、推荐关联和直接后续以 `data/catalog.*` 为唯一事实源。

内容页面不得自行复制或修改这些关系。页面只能读取图谱关系，避免出现同一事实的两份版本。

## 3. 页面 Schema

结构化内容遵循 `schemas/knowledge-page.schema.json`。

核心字段：

- `slug`
- `title`
- `tier`
- `status`
- `kind`
- `summary`
- `why`
- `learningObjectives`
- `coreTopics`
- `syllabus`
- `resources`
- `exercises`
- `projects`
- `completion`
- `sources`

## 4. 内容深度

### 基础页

所有知识节点都必须可访问。基础页至少包含图谱简介、核心内容、前置关系、后续关系和三级完成标准。

### 标准页

核心约 80—120 个节点升级为标准页，增加：

- 明确学习目标；
- 完整课程结构；
- 教材与公开资源；
- 练习方向；
- 项目；
- 经过编辑的完成标准。

### 精品页

首批约 20—30 个核心节点进一步加入章节正文、例题、作业、项目、参考答案与深入学习指南。

## 5. 来源政策

事实与资源优先级：

1. 大学官方培养方案与课程主页；
2. 教师官方 syllabus 与讲义；
3. 标准教材与出版社信息；
4. 高质量开放课程；
5. 其他可靠资料。

AI 不得凭记忆编造课程号、教材、教师、链接或机构信息。未核验资源必须标记 `待核验`；只有真实检查过的资源才能标记 `已核验`。

## 6. 完成标准

可学习节点统一采用三级完成标准：

- `basic`：基础完成；
- `proficient`：熟练掌握；
- `researchReady`：研究准备。

标准必须可验证，禁止只写“了解、熟悉、掌握”。数学应强调证明与问题求解，计算机应强调实现和系统实验，人工智能应强调推导、实现、实验设计和误差分析。

## 7. 章节与图谱边界

课程章节默认只存在于 `syllabus` 中，不自动升级为全局知识节点。

只有具有明显跨课程复用价值、独立前置关系或长期导航价值的主题，才由人工审核后加入主图谱。

## 8. 发布状态

页面状态：

`draft → validated → reviewed → published`

自动生成内容默认只能进入 `draft`。校验通过后可以进入 `validated`；人工审核后进入 `reviewed`；正式对外稳定展示的页面标记为 `published`。

人工编辑过的 `reviewed` 或 `published` 页面不得被批处理 Agent 静默覆盖。

## 9. 自动化验收

CI 至少检查：

- Schema 基础字段合法；
- slug 唯一；
- 页面能够映射到现有知识节点；
- 页面没有自行维护图谱关系；
- 完成标准完整；
- 资源记录带验证状态；
- JavaScript 与静态页面可构建。

后续自动化继续增加：URL 可访问性、中文术语一致性、层级越级检查、重复内容检测与来源可信度检查。

## 10. 当前压力测试节点

第一批结构化标准页使用四种不同对象验证 Schema：

- 实分析 I：数学理论课程；
- 操作系统：计算机系统课程；
- 机器学习：人工智能理论与实验课程；
- 命令行与 Git：工具与实践节点。

如果同一套页面系统能自然容纳这四类对象，再开始大规模生成其余节点。

## 11. 三层内容边界

知识页面的内容正式分成三层：

### KnowledgeNode

知识节点负责稳定知识标准，包括：

- 核心问题；
- 学习目标；
- canonical syllabus；
- 完成标准；
- 从主图谱动态读取的前置、推荐与后续关系。

### CourseImplementation

课程实现描述某个真实大学、公开课程或标准教学体系如何教授知识节点，遵循 `schemas/course-implementation.schema.json`。

课程实现可以包含学校、课程号、课程版本、覆盖主题、实验与项目特点、课程风格维度和官方来源，但不能把社区难度、个人建议、最难章节等主观经验字段混入其中。

课程风格维度只用于描述，不计算总分，也不建立全局排行榜。

### LearningExperience

学习经验遵循 `schemas/learning-experience.schema.json`，用于保留社区项目、维护者或学习者的主观反馈。

它可以包含：

- 实际投入时间；
- 难度；
- 常见难点；
- 最有价值部分；
- 建议前置；
- 学习建议。

这些字段必须明确标记为“社区经验 / 主观经验”，不能作为官方课程事实，也不能自动进入 canonical syllabus。

## 12. 社区项目的角色

REKCARC、CS DIY、HackWay 等项目主要作为：

- discovery 来源；
- 课程与资源候选池；
- learning experience 来源。

其中课程号、年份、当前状态、prerequisites、syllabus、lab、project、教材和官方链接应尽可能回到大学或教师的一手来源核验。

具体生产流程见 `docs/CONTENT_RESEARCH_WORKFLOW.md`。
