# 内容研究流水线 v1

本文件定义单个标准知识页从候选发现到审核发布的生产流程。目标是让内容具有可追溯的一手来源，同时保留社区经验，但不把主观评价混入知识本体。

## 三层内容模型

### KnowledgeNode：知识节点

知识节点是稳定知识本体，例如“实分析”“操作系统”“机器学习”。

它负责：

- 为什么学习；
- 学习目标；
- 核心内容；
- canonical syllabus；
- 完成标准；
- 图谱中的前置、推荐和后续关系。

其中领域、层级、学科群、必要前置、推荐关联和直接后续继续以 `data/catalog.*` 为唯一事实源。

### CourseImplementation：课程实现

课程实现描述某个真实大学、公开课程或教学体系如何教授一个知识节点。

它负责：

- 学校、课程号和课程名称；
- 当前或历史版本；
- 课程覆盖主题；
- lab、project、proof-heavy 等课程特点；
- 课程风格维度；
- 官方课程链接和一手来源。

课程实现不是知识节点，也不参与全局知识本体的唯一性判断。

### LearningExperience：学习经验

学习经验保留社区项目、维护者和真实学习者的主观反馈，例如：

- 实际投入时间；
- 难点；
- 最有价值的部分；
- 建议前置；
- 学习建议。

这些内容必须明确标记为“社区经验 / 主观经验”，不能伪装成学校官方要求，也不能自动写入 canonical syllabus。

---

## Phase 1 — Discovery

先扫描高质量社区项目和成熟课程导航，建立候选池。

当前重点参考：

- REKCARC-TSC-UHT
- CS DIY
- HackWay

这些来源只负责：

- 发现优秀课程；
- 发现教材、lab、project、讲义线索；
- 理解学习者真实体验；
- 找到可能值得核验的课程映射。

禁止在这一阶段把社区项目中的课程号、学时、难度、课程评价直接当成官方事实写入 `CourseImplementation`。

输出：

- 候选课程列表；
- 候选教材与资源列表；
- 候选学习经验；
- 需要回到一手来源核验的问题清单。

---

## Phase 2 — Primary Source Verification

对候选课程回到第一手资料核验。

优先级：

1. 大学官方课程主页；
2. 教师官方 syllabus / lecture notes；
3. 官方课程仓库；
4. 教材官网 / 出版社；
5. 其他第一手资料。

必须验证：

- 课程名称；
- 课程号；
- 开设年份或版本；
- prerequisites；
- syllabus；
- labs；
- projects；
- 教材；
- 资源链接；
- 当前课程与历史版本的关系。

所有链接应保存来源类型和核验状态。

无法确认的信息：

- 不猜；
- 不使用模型记忆补齐；
- 保持 `draft` 或“待核验”。

---

## Phase 3 — Canonicalization

知识页中的 syllabus 不是任何一所学校 syllabus 的复制品。

对于标准页，原则上比较至少 3 个成熟课程实现、教材体系或等价的一手教学来源。

目标是提取：

- 该知识节点解决的核心问题；
- 多个成熟课程重复出现的稳定主题；
- 学习目标；
- 典型习题类型；
- 实践或证明要求；
- 三级完成标准。

流程：

```text
多套课程 / 教材
      ↓
共同主题与稳定能力要求
      ↓
canonical syllabus
      ↓
KnowledgeNode 标准页
```

如果不同学校对课程边界差异很大，应在研究记录中明确分歧，而不是强行合并成虚假共识。

---

## Phase 4 — Draft

把 canonicalization 的结果写入 `knowledge-page.schema.json`。

规则：

- 自动生成内容默认 `status = draft`；
- 不在页面文件中复制 `domain / stage / cluster / prerequisites / recommended / next`；
- 图谱关系继续动态读取 `data/catalog.*`；
- 教材和公开资源必须带核验状态；
- 课程实现写入 `content/courses/`；
- 社区经验写入 `content/experiences/`；
- 三类对象不得混写。

---

## Phase 5 — Audit

由独立审核步骤检查：

### 事实

- 是否编造课程；
- URL 是否真实可访问；
- 课程号是否变化；
- 当前课程与历史版本是否混淆；
- 教材、教师、学校是否有一手来源；
- 是否把社区经验写成官方事实。

### 结构

- 是否与图谱前置关系冲突；
- 是否缺少公认核心内容；
- 是否加入明显越级内容；
- 是否把章节误升级成全局知识节点；
- 是否把某一所学校 syllabus 直接冒充 canonical syllabus。

### 内容质量

- 是否存在大量空话；
- 是否重复其他知识节点内容；
- 学习目标是否可验证；
- 完成标准是否可执行；
- 实践型课程是否有实现或实验要求；
- 数学课程是否保留证明和问题求解要求；
- AI 课程是否包含推导、实现、实验设计与误差分析。

### KnowledgePage

`draft → validated → reviewed → published`

### CourseImplementation

`draft → validated → reviewed`

`unverified → reviewed`

自动化不得静默覆盖 `reviewed` 或 `published` 内容。

## 社区来源使用边界

### REKCARC

适合：

- 真实学生课程经验；
- 教材与课程资源线索；
- 清华计算机课程学习语境。

不直接作为：

- 官方课程事实；
- canonical syllabus 的唯一依据。

### CS DIY

适合：

- 国外高质量公开课程候选；
- workload、难度和实践体验等社区评价；
- lab / project / prerequisite 线索。

其中 workload 和 difficulty 默认属于主观经验层，除非大学官方页面明确给出。

### HackWay

适合：

- 学校培养方案和课程映射候选；
- 新旧课程号关系线索；
- 专业路径整理。

课程编号、培养方案和当前开设状态必须回到学校官方来源核验。
